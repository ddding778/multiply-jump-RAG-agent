# 技术选型

本文只记录已确认的关键选择及其简短理由；具体调用方式见 [rag链路.md](rag链路.md)。

## 技术文档 RAG V2

| 问题 | 选择 | 为什么这样做 |
| --- | --- | --- |
| 云端 embedding 厂商可能调整 | 使用 OpenAI-compatible 接口；当前使用 DashScope `qwen3.7-text-embedding`、1024 维 | 调用合同稳定，后续替换模型或供应商时影响范围较小。 |
| Markdown 在固定 token 处截断会丢失语义 | 标题树 + 自然语义块切分；800 token 优先、1200 token 硬上限 | 保留标题、段落、句子与代码块的语义边界，同时控制 embedding 输入大小。 |
| 同一章节被切成短块后缺少上下文 | 命中后仅按 P1 读取真实前后邻居，并限制同标题或同父标题 | 补充上下文，但不扫描整个章节，避免跨标题污染和无界延迟。 |
| 新索引可能覆盖旧版本的 Qdrant point | 每个 `index_version` 使用独立 collection | 可以明确切换和回退版本，不会让旧版本因同一 point ID 被覆盖而不完整。 |
| Qdrant 向量与本地 BM25 可能不是同一批数据 | manifest、BM25 artifact 与 collection 绑定；在线启动时强制校验 | 避免向量和词法索引混用后产生不可解释的召回结果。 |
| Dense 容易漏掉标识符、术语等词法命中 | Dense 与 BM25 各取候选，经加权 RRF 合并，再用 MMR 去重 | 保留语义召回能力，同时补足精确词法匹配并减少重复片段。 |
| 检索参数直接写死难以验证 | RRF/MMR/BM25 参数放入 `app/ragservice/config/rag-retrieval.yaml` | 参数可独立评测和回滚；只调排序参数时无需重建索引。 |
| 把 Dense、BM25、RRF、MMR 分拆为四种评测会放大成本且偏离目标 | 只评测 Dense 基线和完整 Hybrid 链路；每题只生成一次 query embedding | 直接回答“完整链路是否优于朴素检索”，并避免把 embedding API 调用量放大。 |
| RAG 文档可能含有恶意指令 | RAG 结果、用户输入和外部工具输出均当作不可信数据 | 参考资料只能补充事实，不能改变系统指令、权限或服务端控制流。 |

当前 RAG 已完成切分、索引、在线检索和校准集评测。rerank、检索 tracing 及保留评测集验证仍未完成。
